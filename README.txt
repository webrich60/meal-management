健康食事アドバイザー v1.7.1（食事登録の表示・照合修正版）
2026-10-28

【今回の不具合】
「昼ご飯」を保存しても朝・昼・夜の状態が全部「未登録」のままになるケースを修正しました。
原因として、旧GASが dayStatus の問い合わせを解釈せず従来の履歴配列を返した場合、旧画面はこれを登録無しと誤認していました。
実際の本番環境での原因の確定は、GASの配布済みバージョンと接続先を確認するまでできません。

【修正内容】
1. GASの応答形式が違う、または通信エラーの場合は「確認できません」と表示し、食事抜けと誤判定しません。
2. 旧版のGASが直近50件の履歴を返した場合、見つかった食事のみ「登録済み」と表示し、他は「確認できません」とします。
3. GAS側で日付の照合にスプレッドシートの表示日とタイムゾーンを使い、複数の食事記録シートも調べます。
4. 「[昼食]」「[昼ご飯]」「【夜ご飯】」などの表記揺れを吸収します。
5. 体重だけの記録を朝・昼・夜の食事として誤判定しないよう修正しました。
6. 保存先のシートIDを記録し、閲覧中のタブが変わっても参照先が切り替わりにくいようにしました。
7. 食事保存成功後に表示との照合が一致しない場合は「保存済み・表示未照合」と表示します。
8. 「取得元シート名／照合日／該当件数／APIバージョン」を食事登録欄の下に追加しました。
9. v1.7.0の体重分析、間食アラート、食事漏れ通知、おかわり・個数補正は維持しています。

【更新方法：必須！】
(1) GAS（先に実施）
  Googleスプレッドシート → 拡張機能 → Apps Script
  既存のCode.gsをバックアップしてから、ZIP内のCode.gsで全文置換して保存。
  デプロイ → デプロイを管理 → 既存Webアプリの鉛筆アイコン → 新バージョン → デプロイ。
  「新しいデプロイ」を作るのではなく、既存デプロイを更新します。URL・APIキーは原則変更不要。
(2) GitHub Pages
  まず mobile-v171.html をGitHubに追加し、テストページを開きます。
  動作確認後、index.htmlをGitHubの既存ファイルに上書きしてCommit。
  スマホの画面を再読み込みしてください。キャッシュで以前の表示が残る場合はブラウザのサイトデータを更新してください。

【テスト手順】
・食事を記録した日付を選び、「↻ 更新」を押します。
・昼食を既に記録している日は「昼ご飯：登録済み」になり、下に「API：1.7.1」と表示されることを確認。
・「API：旧版」と出たら、GASの新バージョン再デプロイを確認してください。
・「該当：0件」で保存した記録が存在する場合は、表示中の照合日と取得元シート名を確認してください。
・「確認できません」は未登録を意味しません。
・登録済みの食事を再度登録して試す必要はありません。重複登録を避けてください。

【テストの範囲と制限】
Code.gsと画面JavaScriptは構文チェック済み。模擬シートを用いた、当日朝・昼の検出、別タブの照合、体重だけの記録の除外、日付差のテストは通過済み。
本番GASのデプロイ、実運用シートへの書き込み、スマホ端末実機の操作はここでは実施していません。
過去の記録は削除しません。食事写真は従来どおりGoogle Driveに保存しません。
