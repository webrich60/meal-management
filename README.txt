■ 今回の変更
1. 食事登録漏れチェック
  選択した日付の朝ご飯・昼ご飯・夜ご飯が「登録済み／食べなかった／未登録」のどれか、Googleスプレッドシートの実記録で判定。
  食事の登録予定時刻を過ぎても未登録の場合、ホーム画面に注意メッセージと「食べたか確認する」ボタンを表示。
  昼ご飯を選び、朝ご飯が未登録なら「朝ご飯は食べましたか？」と確認します。
  「はい」→朝ご飯の入力画面へ。
  「いいえ」→朝ご飯を「食事なし（スキップ）」としてGASへ保存し、元の昼ご飯の操作へ。
  「あとで」→未登録のまま先へ。食べなかった扱いにはしません。
  夜ご飯を選ぶと、朝→昼の順で未確認食事をチェックします。
  現在時刻より先の食事を早すぎる「登録漏れ」として強調しません。

2. 間食アラート
  ビスケット、クッキー、ポテトチップ、スナック菓子、菓子パン、チョコなどを間食として記録すると注意表示。
  同系統の菓子を過去7日間にも記録していた場合、回数を示し連続摂取に注意を促します。
  ヨーグルト系のみの間食には警告しません（ヨーグルトと菓子を同時に食べた場合は対象）。
  実際に食べた個数で補正された栄養値からも判定します。
  警告内容は食事記録・AI分析の参考であり、食べた人を非難する目的ではありません。

3. 体重と食事の分析強化
  元の食事記録シートのほか、同じスプレッドシート内で「日付・体重」の列が存在する別シートも探索します。
  「体重増加リスク」列を「体重」列と誤検出しないようにしました。
  3か月・半年レポートへ日付ごとの体重、日別・週別食事集計、前半・後半の記録がある日の平均、菓子系間食回数、個数やおかわりを入力。
  未登録の日は「何も食べず0kcalだった日」とみなしません。
  過去のすべての日を自動で再解析しているわけではありません。過去のカロリー等は保存時の推定値です。
  記録から分かる相関と、運動量・睡眠・むくみ等の未観測要因は区別します。
  今日の体重が同日のスプレッドシートにある場合は入力欄に復元します。

4. データ互換性
  過去の食事・体重データは削除・初期化しません。従来のA～Z列を維持します。
  GASが追加するのはAA列「間食分類」です。古い間食の分類は料理名等から可能な範囲で推定します。
  既存のGAS URL、Gemini APIキー、Google スプレッドシートIDを変更する必要はありません。
  食事写真は引き続きGoogle Driveに保存しません。

■ 必ず行う更新作業
【先にGAS更新】
1. 食事管理に利用しているGoogleスプレッドシートを開く。
2. 「拡張機能」→「Apps Script」から既存プロジェクトを開く。
3. 既存のCode.gsを念のためバックアップする。
4. Code.gs全文をZIPの最新Code.gsで置き換えて保存する。
5. 「デプロイ」→「デプロイを管理」→既存のウェブアプリを編集（鉛筆）。
6. 「バージョン：新バージョン」を選び「デプロイ」。
7. 既存WebアプリURL（/exec）はそのまま利用する。

【次にGitHub Pages更新】
1. GitHubのmeal-managementリポジトリに「mobile-v170.html」を追加（テスト用）。
2. https://webrich60.github.io/meal-management/mobile-v170.html を開いて挙動を確認。
3. 問題なければZIP内の「index.html」で既存のindex.htmlを上書きし、Commitする。
4. https://webrich60.github.io/meal-management/ を再読み込み（スマホで古い画面が残る場合はキャッシュも更新）。
5. 環境設定（呼び名、身長、GAS URLなど）を確認。設定は従来の端末保存を継続。

■ 最低限の動作確認
- 同日の朝ご飯が未登録の状態で昼ご飯ボタンを押す。「朝ご飯は食べましたか？」が出ること。
- 「はい」で朝ご飯登録へ、「いいえ」で食事なしの保存になること。
- 間食に「ビスケット」を登録すると警告が出ること。
- 間食に「ヨーグルト」を登録すると特別な菓子警告が出ないこと。
- 実際に食べた量、おかわりの数を指定すると結果の栄養値へ反映されること。
- 体重データが別日に2件以上あると3か月・半年の分析が動くこと。
- スプレッドシートのAA列に新しい間食分類が作成されること。

■ テストの範囲と注意
JavaScriptの構文検証、GASの疑似スプレッドシートでの計算テスト、390pxスマホ幅での操作テストを実施済みです。
本番のスプレッドシートとGemini APIへの接続、実運用データを使った動作、実際の再デプロイは実施していません。
本番でうまく体重取得できない場合は、体重列の見出し、測定日列、データを確認してください。診断はせず、データの傾向を補助的に示すアプリです。
急激な体重増加やむくみなどがある場合は食事原因と決めつけず医療機関へ相談してください。
